## 🏛️ BCSE307L Database Systems Architecture

The database layer is normalized to **Third Normal Form (3NF)** and implemented with **PostgreSQL** and **Prisma ORM**.

### 1. Relational Entities (19 Tables in 3NF):
1. **`Role`**: Authorization tiers (`ADMIN`, `CUSTOMER`).
2. **`User`**: Hashed credentials (bcrypt), profiles, and role assignments.
3. **`AutomotiveProject`**: Vehicle programs (Apex Hyper-GT, Terra SUV, Pulse Sedan), budgets, timelines, and stored-procedure driven completion percentage.
4. **`ProjectMember`**: M:N relational team junction linking engineers and program managers to vehicle programs.
5. **`VehicleModel`**: Vehicle model lines, model codes, segments (Hyper-GT, Electric SUV, Performance Sedan), and model years.
6. **`VehicleVariant`**: Drivetrain derivatives (Dual-Motor AWD, Tri-Motor Performance), base pricing, and status.
7. **`VehicleSpecification`**: 1:1 normalized technical telemetry (range, 0–100 acceleration, top speed, power, battery kWh, curb weight, drag coefficient).
8. **`ComponentCategory`**: 12 automotive categories (Powertrain, Battery, Suspension, Brakes, Wheels, Tyres, Interior, Aero, etc.).
9. **`Supplier`**: Certified Tier-1 automotive suppliers (Bosch, Brembo, Samsung SDI, Michelin, Bilstein, Recaro, Magna Steyr, Continental).
10. **`Component`**: Precision parts with part numbers, weights, costs, CAD mesh types, and approval lifecycle states.
11. **`ComponentSupplier`**: M:N decomposition linking parts with suppliers, lead times, and unit costs.
12. **`ComponentSpecification`**: EAV normalized electrical, mechanical, and thermal parameters.
13. **`VariantComponent`**: M:N decomposition mapping standard and optional components to vehicle variants with 3D positional offsets.
14. **`ThreeDModel`**: 3D mesh LOD levels, geometry counts, and shader rendering properties.
15. **`VehicleConfiguration`**: User-customized configurations with persisted configuration codes, calculated pricing, and mass totals.
16. **`ConfigurationComponent`**: Junction entity recording selected optional components, custom CMF overrides, and options.
17. **`ProjectMilestone`**: Stage-gate engineering milestones with target dates, completion weights, and completion status.
18. **`EngineeringReview`**: Compliance audits (Aerodynamics CFD, Thermal Runaway, FEA Crash Safety, NVH) with scores and sign-offs.
19. **`AuditLog`**: Immutable ledger capturing state transitions automatically generated by database triggers.

### 2. Advanced Relational Constructs:

#### A. Database View (`VehicleComponentView`):
Unifies 5 relational tables to provide an integrated view of vehicle models, variants, components, categories, and certified suppliers:
```sql
CREATE OR REPLACE VIEW "VehicleComponentView" AS
SELECT 
    vm.model_code, vm.name AS model_name, vv.variant_code, vv.name AS variant_name,
    c.part_number, c.name AS component_name, c.weight_kg, c.cost_usd,
    cc.name AS category_name, s.name AS supplier_name, s.tier_level
FROM "VehicleModel" vm
JOIN "VehicleVariant" vv ON vm.id = vv.model_id
JOIN "VariantComponent" vc ON vv.id = vc.variant_id
JOIN "Component" c ON vc.component_id = c.id
JOIN "ComponentCategory" cc ON c.category_id = cc.id
LEFT JOIN "ComponentSupplier" cs ON c.id = cs.component_id
LEFT JOIN "Supplier" s ON cs.supplier_id = s.id;
```

#### B. Stored Procedure (`calculate_project_completion`):
Computes weighted milestone progress across all engineering milestones and updates `AutomotiveProject.completion_percentage`:
```sql
CREATE OR REPLACE FUNCTION calculate_project_completion(p_project_id TEXT)
RETURNS FLOAT AS $$
DECLARE
    v_total_weight FLOAT := 0;
    v_completed_weight FLOAT := 0;
    v_completion_pct FLOAT := 0;
BEGIN
    SELECT COALESCE(SUM(weight), 0), COALESCE(SUM(CASE WHEN is_completed = true THEN weight ELSE 0 END), 0)
    INTO v_total_weight, v_completed_weight
    FROM "ProjectMilestone" WHERE project_id = p_project_id;

    IF v_total_weight > 0 THEN
        v_completion_pct := ROUND(((v_completed_weight / v_total_weight) * 100)::numeric, 1);
    ELSE
        v_completion_pct := 0;
    END IF;

    UPDATE "AutomotiveProject"
    SET completion_percentage = v_completion_pct, updated_at = NOW()
    WHERE id = p_project_id;

    RETURN v_completion_pct;
END;
$$ LANGUAGE plpgsql;
```

#### C. Database Triggers:
1. `update_project_timestamp`: Updates `updated_at` whenever an `AutomotiveProject` record is modified.
2. `audit_milestone_update`: Fires on milestone state modification, inserting an audit snapshot into `AuditLog`.

#### D. Performance B-Tree Indexes:
Indexes created on `part_number`, `project_code`, `category_id`, `supplier_id`, `variant_id`, and `status`.

## 🚀 Quickstart Guide

### Prerequisites:
- Node.js >= 20
- npm >= 10

### 1. Install & Setup Database:
```bash
# Install dependencies across monorepo (root, server, client)
npm run install:all

# Generate Prisma client, push 3NF schema, and seed realistic automotive dataset
npm run db:setup
```

### 2. Run Automated Test Suite:
```bash
npm run test --prefix server
```
*Executes all 5 database integration tests verifying 3NF normalization, 5-table joins, aggregate queries, ACID transactions, and stored procedure execution.*

### 3. Run Development Server:
```bash
npm run dev
```
- **Frontend**: `http://localhost:3000` (Vite with sub-50ms HMR)
- **Backend API**: `http://localhost:5000` (Express + Prisma + REST API)
- **API Health**: `http://localhost:5000/api/health`

### 4. Build for Production:
```bash
npm run build
npm start
```
